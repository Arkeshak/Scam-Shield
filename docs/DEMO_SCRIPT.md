# Three-minute demo script

**Only use the family-alert shot after linking two consenting Telegram test
accounts and verifying a real delivered alert. Do not stage a fake notification.
If that manual test is unavailable, state that it is not verified and use the
time to show the tested offline guardrail instead.**

## 0:00–0:40 — Headline: Live Call Guard (Real-Time Speakerphone Monitor)

**Spoken first line:** “Pre-existing: nothing. Everything was built this week for the Meta Global AI Hackathon.”

“Phone scams happen in seconds. With our headline feature, **Live Call Guard**, an elder puts any suspicious phone call on speakerphone. Live audio streams via WebSocket to Meta’s **Muse Voice Transcribe realtime endpoint**. The instant pressure tactics appear—demanding an OTP, requesting secrecy, or threatening arrest—the screen flashes red with a high-contrast warning: **HANG UP IMMEDIATELY**, while silently dispatching a Telegram alert to their family.”

**Action:** Open `/guard`. Tick consent, click *Test with an audio file* (or speak into the mic), select `call_01_synthetic_bank_otp.wav`. Watch real-time streaming: turn transcribed, banner flashes red, audible alert sounds, and threat tags (`Code`, `Secrecy`) appear.

## 0:40–1:00 — Problem & Message Flow
“Family members also receive strange messages. ScamShield explains the trick simply and verifies links.”
**Click:** Open the main page; select **Message**; choose **Bank SMS**. Show the result, local link check, agent steps, and model badges.


## 0:20–1:05 — Screenshot flow (45 seconds)

**Click:** Select **Screenshot**. Upload `data/demo_screenshot.png`, generated by
`python tools/make_demo_screenshot.py`, then click **Check it**.

**Say:** “This is an invented parcel notice and fake `.invalid` address. Muse
Spark identifies suspicious content; SAM 3.1 attempts a box for the concrete
button. Green means a SAM box; red means the rough analysis box.”

Wait for the result. Point out the matching legend. If SAM returns no box, say so
and show the returned result honestly; do not replace it with a fabricated box.

## 1:05–1:40 — Voice note and agent (35 seconds)

**Click:** Select **Voice note** and upload an authorized synthetic recording
(English or Tamil), then click **Check it**.

**Say:** “Muse Voice Transcribe turns the recording into text, then the agent
checks the request. The web-search sources are shown only when the model returns
them. Sinhala transcription is not supported; text and screenshots still work.”

Point at the transcript, actions, and any cited sources. Do not use a real
person’s recording or message.

## 1:40–2:25 — Family alert (45 seconds)

**Only if verified:** Show two consenting Telegram test accounts. On the elder
account, submit the fictional **Family emergency** example. Show the real alert
arrive on the linked guardian account.

**Say:** “The alert is sent only after the risk/action checks and a guardian link.
If image generation fails, the bot falls back to a text alert.”

If two-account delivery has not been tested, say: “The tool and fake-model
guardrails are tested, but a live family alert is not verified yet.” Show
`/status` or the offline test proving low-risk cases do not enqueue alerts. Do not
pretend this is a live notification.

## 2:25–2:50 — Numbers and tools (25 seconds)

Show **Evaluation details** from `data/eval_results.json` and the tools table in
the README. Read the actual case count, coverage, false alarms, missed scams,
and worst mistakes. State if the run has failed/unavailable cases. Do not describe
synthetic evaluation as real-world accuracy.

## 2:50–3:00 — Privacy and limits (10 seconds)

“Message content is not stored. Model answers can be wrong, so verify through
official channels. Sinhala voice and real family-device delivery need their
stated limits and test results.”
